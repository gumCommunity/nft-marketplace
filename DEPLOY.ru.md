# Развёртывание маркетплейса (testnet → mainnet)

Что получится в итоге:

- **контракт маркетплейса** в сети (кошелёк v3r2 от Getgems, управляется ключом администратора);
- **тестовая коллекция NFT** (по желанию), из которой можно минтить NFT для проверки;
- **стенд** на GitHub Pages: подключаете кошелёк, выставляете NFT за фиксированную цену или на аукцион (TON или GUM),
  покупаете, делаете ставки, отменяете и завершаете.

Контракты продаж и аукционов при развёртывании не деплоятся: их создаёт продавец со стенда, отдельный контракт на каждый лот.

## 0. Что нужно

- Node.js 22+, git.
- Кошелёк с TON (Tonkeeper / MyTonWallet). Для testnet переключите кошелёк в testnet и получите тестовые TON
  в [@testgiver_ton_bot](https://t.me/testgiver_ton_bot). На всё развёртывание хватит ~1 TON.
- Для проверки покупок второй кошелёк (покупатель) с TON и, для оплаты в GUM, с тестовыми GUM.

## 1. Репозиторий на GitHub

Создайте **публичный** репозиторий `gumCommunity/nft-marketplace`, пустой, без README. Затем:

```bash
cd nft-marketplace
git remote add origin https://github.com/gumCommunity/nft-marketplace.git
git push -u origin main
```

> Если репозиторий называется иначе, стенд будет по другому адресу. Тогда **до шага 4** замените
> `https://gumcommunity.github.io/nft-marketplace/` на свой адрес в `web/public/tonconnect-manifest.json` и
> `web/public/test-nft/*.json`, а при деплое коллекции передайте `STAND_URL=https://<org>.github.io/<repo>/`.

## 2. Установка и тесты

```bash
npm ci
npm test        # 25 тестов: код = исходники Getgems, все сценарии продаж/аукционов в песочнице
```

## 3. Маркетплейс в testnet

```bash
npx blueprint run deployMarketplace --testnet
```

Blueprint спросит, каким кошельком платить за деплой (TON Connect — QR-код для Tonkeeper, или мнемоника из `.env`:
`WALLET_MNEMONIC="..."` и `WALLET_VERSION=v4`/`v5r1`).

Скрипт:

1. создаёт **ключ администратора** и дописывает его в `.env` как `MARKETPLACE_ADMIN_MNEMONIC_TESTNET`
   (если ключ там уже есть, использует его). **Сделайте резервную копию `.env`**: без ключа маркетплейсом не управлять;
2. спрашивает **адрес для комиссии** (по умолчанию ваш кошелёк) и **процент комиссии** (например `5`);
3. деплоит контракт маркетплейса с 0.5 TON на балансе (из него оплачиваются админские действия);
4. записывает адрес, комиссию и публичный ключ в `deployments.json`.

Повторный запуск с тем же ключом даёт тот же адрес: контракт не передеплоится, обновятся только настройки
(например, процент комиссии).

## 4. Тестовая коллекция (по желанию)

```bash
npx blueprint run deployTestCollection --testnet 5      # 5 = роялти коллекции в %, получатель — ваш кошелёк
npx blueprint run mintTestNft --testnet 3               # 3 NFT на ваш кошелёк (или кнопкой на стенде)
```

Минтить может только владелец коллекции, то есть кошелёк, которым её деплоили. Метаданные и картинки лежат на самом
стенде (`web/public/test-nft/`), поэтому они появятся после шага 6.

Тестовая коллекция не обязательна: на стенде можно выставить любую NFT из кошелька, например ваучеры Gumcoin.

## 5. Ключ tonapi (по желанию)

Без ключа tonapi отвечает примерно на 1 запрос в секунду, и стенд загружает лоты медленно. Ключ берётся на
[tonconsole.com](https://tonconsole.com), кладётся в `web/.env.local`:

```
VITE_TONAPI_KEY=...
```

Ключ попадает в публичный JavaScript, поэтому используйте ключ для браузера, не серверный.

## 6. Публикация стенда

Один раз в репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch → `gh-pages` / `(root)`**.

Затем, после каждого изменения `deployments.json` или кода:

```bash
npm run deploy:web     # собирает страницу с deployments.json и пушит web/dist в ветку gh-pages
git add deployments.json && git commit -m "testnet deployment" && git push
```

Через 1–2 минуты стенд доступен:

- testnet: https://gumcommunity.github.io/nft-marketplace/
- mainnet: https://gumcommunity.github.io/nft-marketplace/?net=mainnet

Локально: `npm run dev` → http://localhost:5173. С телефона кошелёк к `localhost` не подключится: проверяйте на
опубликованной странице.

## 7. Проверка на testnet (чек-лист)

Кошелёк **A** — продавец, **B** — покупатель, оба в testnet.

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | A: «Test collection» → Mint (2–3 раза) | NFT появляются на вкладке «My NFTs» |
| 2 | A: NFT → Sell… → Fixed price, TON, 1 | лот на вкладке «Listings», статус *on sale* |
| 3 | B: Buy for 1 TON | NFT у B; A получает 1 − комиссия − роялти; адрес комиссии получает комиссию |
| 4 | A: другую NFT на продажу, затем Cancel sale | NFT вернулась к A |
| 5 | A: Fixed price в GUM | B покупает за GUM, GUM делятся так же |
| 6 | A: Auction, TON, min 1, buyout 5, шаг 10%, длительность `0.1` ч (6 минут) | лот *on sale* с таймером |
| 7 | B: ставка 1, потом другим кошельком 1.1 | первая ставка вернулась B |
| 8 | После окончания: A или победитель → Finish auction | NFT у победителя, выплаты продавцу, комиссия, роялти |
| 9 | Аукцион с buyout: ставка = buyout | аукцион завершается сразу |
| 10 | Аукцион в GUM | ставки и выплаты в GUM |
| 11 | `npx blueprint run marketplaceAdmin --testnet cancel <адрес лота>` | админ снял лот, NFT вернулась продавцу |

Ставка в последние 5 минут продлевает аукцион на 5 минут (защита от снайпинга).

## 8. Mainnet

Всё то же самое с `--mainnet`:

```bash
npx blueprint run deployMarketplace --mainnet       # отдельный ключ MARKETPLACE_ADMIN_MNEMONIC_MAINNET
npm run deploy:web
git add deployments.json && git commit -m "mainnet deployment" && git push
```

Тестовую коллекцию в mainnet деплоить не обязательно. Стенд для mainnet открывается по ссылке `?net=mainnet`.

Перед mainnet:

- ключ администратора mainnet храните отдельно от рабочего компьютера (менеджер паролей / офлайн);
- проверьте адрес и процент комиссии в `deployments.json`;
- проверьте одну продажу на маленькую сумму.

## 9. Администрирование

```bash
npx blueprint run marketplaceAdmin --mainnet info                        # баланс и seqno маркетплейса
npx blueprint run marketplaceAdmin --mainnet withdraw <адрес> <TON>      # вывести TON с маркетплейса
npx blueprint run marketplaceAdmin --mainnet cancel <адрес лота>         # снять продажу / аукцион без ставок
npx blueprint run marketplaceAdmin --mainnet rescue <адрес лота> [кому]  # вернуть NFT, застрявшую в неактивированном лоте
```

Админские действия подписываются ключом из `.env` и оплачиваются с баланса маркетплейса: каждое отправляет 0.1 TON.
Пополнить баланс можно обычным переводом на адрес маркетплейса. На этот же адрес приходят 0.01 TON за регистрацию
каждого лота.

**Смена комиссии.** Снова запустите `deployMarketplace` с новым процентом и пересоберите стенд. Комиссия зашита в каждый
лот при создании, поэтому старые лоты со старой комиссией со стенда пропадут, хотя в сети продолжат работать:
продавцам лучше их пересоздать.

## Что дальше

Это основа. Для полноценного маркетплейса нужны: индексатор и база (стенд просматривает последние 50 регистраций),
офферы (`nft-offer` у Getgems), страницы коллекций, поиск, смена цены из интерфейса (`change_price` в контракте продажи
уже есть) и, при желании, бэкенд, подписывающий лоты (op 1 маркетплейса, уже покрыт тестами).
